# דוכן 🛍️

פלטפורמה שבה ילדה (9–14) פותחת חנות אונליין קטנה בעצמה, מעלה מוצרים מהטלפון, ומקבלת לינק לשיתוף. קונה בוחרת מוצרים ולוחצת כפתור שפותח וואטסאפ עם ההזמנה מנוסחת מראש. **המערכת לא נוגעת בכסף ולא במשלוח.**

**ארכיטקטורה: דיפלוי אחד, multi-tenant.** כל חנות היא שורה בטבלה `stores`. אין דיפלוי per store.

מסמכים: [`docs/deploy.md`](./docs/deploy.md) (**עלייה לאוויר**) · [`CLAUDE.md`](./CLAUDE.md) (הוראות הבנייה) · [`docs/duchan-spec.md`](./docs/duchan-spec.md) · [`docs/duchan-plan.md`](./docs/duchan-plan.md) · [`docs/duchan-mockup.html`](./docs/duchan-mockup.html)

## סטאק

- **Next.js 15** (App Router) + TypeScript + Tailwind 4
- **Supabase** — Postgres + Auth + RLS
- **Cloudflare R2** — כל המדיה (egress חינם — זה מה שמחזיק את מודל העלות)
- **Vercel** — אירוח (Node runtime; ראי [`docs/deploy.md`](./docs/deploy.md))

## הקמה

לעלייה לפרודקשן על דומיין אמיתי — [`docs/deploy.md`](./docs/deploy.md), כולל רשומות
ה-DNS, הקרון היומי, ומה לבדוק אחרי. מה שלמטה הוא הגרסה המקוצרת לפיתוח מקומי.

### 1. Supabase

1. פרויקט חדש ב-[supabase.com](https://supabase.com) (התוכנית החינמית מספיקה).
2. **Authentication → Sign In / Up → כבי "Confirm email".** ההרשמה קורית בסוף האונבורדינג, אחרי שהילדה כבר בנתה חנות — מסך אימות באמצע שובר את הפלואו.
3. העתיקי מ-Settings → API את ה-URL, ה-anon key וה-service role key.
4. את המיגרציות מריצים בסעיף 4 — לא ידנית ב-SQL Editor.

### 2. Cloudflare R2

1. צרי bucket בשם `duchan-media` והפעילי עליו Public Access עם דומיין (למשל `media.duchan.co`).
2. צרי API Token עם הרשאת Object Read & Write על ה-bucket.
3. הגדירי CORS על ה-bucket כדי לאפשר `PUT` מהאפליקציה:

```json
[{ "AllowedOrigins": ["*"], "AllowedMethods": ["PUT", "GET"], "AllowedHeaders": ["content-type"] }]
```

### 3. משתני סביבה

```bash
cp .env.example .env.local   # ומלאי את הערכים
```

### 4. הרצת המיגרציות

מ-Settings → Database → Connection string (URI) ב-Supabase:

```bash
npm run migrate "postgresql://postgres:<סיסמה>@db.<ref>.supabase.co:5432/postgres"
```

הסקריפט מריץ את `supabase/migrations/*.sql` לפי הסדר ורושם כל אחת ב-`schema_migrations`,
כך שהרצה חוזרת בטוחה. אם כבר הרצת חלק מהן ידנית ב-SQL Editor:

```bash
npm run migrate "<url>" -- --baseline=0007   # סימון 0001–0007 כהורצו, בלי להריץ
npm run migrate "<url>"                      # והרצת השאר
```

### 5. בדיקה שהכל מחובר

```bash
npm run check
```

עובר על משתני הסביבה, מוודא ש-Supabase עונה, שכל העמודות והפונקציות קיימות
(כלומר שאף מיגרציה לא נשכחה), **ש-RLS באמת חוסם אנונימי**, ושה-service key לא
הודבק בטעות במקום ה-anon key. בסוף כותב ל-R2 קובץ בדיקה, קורא אותו מהדומיין
הפומבי ומוחק אותו. כל כשל מודפס עם מה בדיוק לתקן.

### 6. הרצה

```bash
npm install
npm run dev
```

### 7. קרון יומי (חובה בתוכנית החינמית)

Cloudflare Worker עם Cron Trigger יומי שקורא ל:

```
GET https://<domain>/api/cron
Authorization: Bearer <CRON_SECRET>
```

זה עושה שני דברים: מגבה את 3 הטבלאות ל-JSON ב-R2 (ל-Supabase החינמי אין גיבוי), ושומר על הפרויקט ער (פרויקטים חינמיים מושהים אחרי שבוע בלי פעילות).

## בדיקות DB (רצות על Postgres מקומי, בלי Supabase)

```bash
psql -d duchan -f supabase/tests/00-auth-stub.sql        # סימולציית סכמת auth
psql -d duchan -f supabase/migrations/0001_init.sql      # ... וכל המיגרציות בסדר
psql -d duchan -f supabase/tests/db-tests.sql            # 11 קבוצות בדיקה
node  supabase/tests/concurrency.mjs                     # 15 הזמנות בו-זמניות
```

מכוסה: מספור אטומי פר חנות · ניכוי מלאי ב"שולם" (פעם אחת בלבד) · החזרת מלאי בביטול · בדיקות בעלות ב-security definer · מלאי לא יורד מתחת לאפס · בידוד RLS בין חנויות · אנונימי לא רואה כלום · `place_order` תחת עומס מקבילי.

## E2E מלא על סטאק מקומי (בלי חשבונות בכלל)

`supabase/tests/local-stack/` — סביבה שמדמה את Supabase ו-R2 מקומית: PostgREST אמיתי (בינארי) מול Postgres, `supashim.mjs` (auth תואם-GoTrue: signup / login / user / admin), `s3shim.mjs` (אחסון עם presigned PUT), ו-`e2e.mjs` — תסריט Playwright של **31 בדיקות** שמריץ את כל לולאת המוצר:

אונבורדינג עם צילום אמיתי → נרמול טלפון → העלאת תמונה דרך presigned URL → חנות פומבית → סל → הזמנה → אימות הודעת הוואטסאפ (טלפון, פריטים, סה"כ, הערה, מספר) → מלאי לא יורד ביצירה → rate limit 429 → "שולם" מנכה אטומית → הקופה שלי → מצב חופשה → קרון גיבוי → noindex → אפס דליפת טלפון ב-HTML.

הרצה: Postgres מקומי עם המיגרציות + `postgrest-setup.sql`, PostgREST על 3001, שני השימים, `next dev`, ואז `node e2e.mjs`.

`e2e-activation.mjs` — **42 בדיקות** של מסלול התשלום, אמצעי התשלום של הילדה, והרשת: הלינק נעול בטיוטה · ההזמנות
מוחזרות ב-404 · מסך ההפעלה מציג מחיר, מה כלול, ההחזר, וההסבר להורה · הצהרת תשלום
לא מפעילה כלום · **הבעלות מנסה לעדכן `activated_at` עם הטוקן האמיתי שלה ונכשלת** (וגם
`payment_amount` ו-`ref_clicks`), אבל כן עורכת את השדות שלה · המנהלת מאשרת מהחמ"ל
והלינק נפתח מיד · הילדה מגדירה איך משלמים לה וזה מגיע לגיליון ההזמנה · מסך "להפיץ" ·
חברה מגיעה מהחנות, פותחת חנות, והשיוך מופיע באשכול.

גם התצוגה המקדימה של וואטסאפ מכוסה שם: `og:title`, `og:url` מוחלט על הדומיין
האמיתי, ו-`og:image` שנבדק שהוא באמת ניתן להורדה — יחד עם `noindex`. השילוב הזה
מכוון: לא נמצא בגוגל, אבל נראה טוב כששולחים אותו.

`e2e-admin.mjs` (12) ו-`e2e-journey.mjs` (14) מכסים את החמ"ל ואת המסע/פרימיום.

## פיצ'רי ניהול (מעבר לבסיס)

- **מצב חופשה** — השהיה/פתיחה של החנות מההגדרות (blocked שמור לאדמין)
- **הסתרת מוצר** בלי מחיקה (`is_visible`) · **שכפול מוצר** · **סידור** בחיצים (▲▼)
- **מלאי מהיר** (+/−) ישר מרשימת המוצרים
- **שחזור מוצרים שנמחקו** תוך 30 יום (מימוש ההבטחה של soft delete)
- **ביטול הזמנה עם החזרת מלאי** — `cancel_order` אטומית ב-DB; ביטול הזמנה ששולמה מחזיר את המלאי
- **סינון הזמנות** לפי סטטוס + **"הקופה שלי"** (סה"כ ששולם, מס' הזמנות, הכי נמכר)
- **הערה אישית על הזמנה** ("לארוז בורוד") — נראית רק לבעלת החנות

## המסע שלי — שכבת הלמידה

`lib/milestones.ts` — שבע אבני דרך אמיתיות (מוצר ראשון · חמישה מוצרים · עשר כניסות · הזמנה ראשונה · מכירה ראשונה · ₪100 · עשר הזמנות), מחושבות מהנתונים הקיימים בלי טבלה חדשה. לכל אבן דרך שהושגה מוצג **מה למדת** ("₪100 זה לא סכום קטן — זה עסק שעובד, לא מזל"), ולכל אחת שנעולה — מה צריך לעשות. זה מה שהופך את זה מכלי מכירה לכלי שמלמד יזמות, וזה מה שמראים להורים.

המנהלת רואה את המסע של כל ילדה בחמ"ל — הן ברשימת החנויות (🎯 מסע: 4/7) והן בתיק החנות המלא.

## ✨ כתיבת תיאורים ב-AI (פרימיום)

הילדה מצלמת מוצר ולוחצת "כתבי לי תיאור" — Claude רואה את התמונה וכותב תיאור קצר בעברית, שהיא יכולה לערוך. **מודלק פר חנות מהחמ"ל** עם מכסת קרדיטים (ברירת מחדל 50), כך שאפשר למכור את זה כשדרוג.

- הפעלה: `ANTHROPIC_API_KEY` ב-env. בלעדיו הכפתור פשוט לא קיים.
- מודל: `AI_MODEL` (ברירת מחדל `claude-opus-5`; `claude-haiku-4-5` זול פי ~5 ומספיק למשימה)
- קרדיטים מנוכים אטומית ב-DB (`use_ai_credit`) ומוחזרים אם הקריאה נכשלה
- המפתח לעולם לא מגיע לדפדפן; הבעלות והפרימיום נאכפים בשרת לפני כל קריאה

**עלות משוערת לתיאור** (תמונת 900×900 ≈ 1,100 טוקנים + פרומפט, פלט ~60 טוקנים):

| מודל | לתיאור | 1,000 תיאורים |
|---|---|---|
| Haiku 4.5 | ~0.6 אגורות | ~₪6 |
| Opus 5 | ~3 אגורות | ~₪30 |

## 💳 הפעלת חנות — תשלום חד-פעמי

**בונים בחינם, משלמים רק כשרוצים לפרסם.** חנות חדשה נשמרת כטיוטה (`activated_at is null`):
הלינק שלה מציג "בהכנה", ה-API של ההזמנות מחזיר 404, וכפתורי השיתוף בדשבורד נעולים.
הכל בנוי ושמור — רק הפרסום חסום.

הפלואו: הילדה בונה → רוצה לשתף → `/activate` מסביר כמה ומה כלול (כולל כפתור
"שליחת ההסבר להורה בוואטסאפ", כי ההורה הוא זה שמשלם) → משלמים בביט/פייבוקס →
לוחצת "שילמנו" → החנות נכנסת לתור בחמ"ל → המנהלת מאשרת בקליק → הלינק נפתח מיד.

- **אין סליקה ואין שמירת פרטי תשלום.** התשלום ישיר למנהלת, האישור ידני. זו החלטה מכוונת.
- `/price` — דף פומבי שמסביר את המחיר לשני הקהלים: מה היא מקבלת, כמה מכירות מחזירות
  את ההשקעה, ומה היא לומדת (להורה). מקור אמת יחיד ב-`lib/pricing.ts`.
- **הבעלות לא יכולה להפעיל את עצמה.** `own_store` הוא policy רחב, ולכן ההגנה היא טריגר
  (`guard_store_activation`, מיגרציה 0008) שמקפיא `activated_at`, `payment_amount`,
  `referred_by` ו-`ref_clicks` בכל UPDATE שמגיע ממשתמשת מזוהה. נבדק ב-E2E עם טוקן אמיתי.

### שני סוגי כסף, ואין ביניהם קשר

| | התשלום לדוכן | הכסף של הילדה |
|---|---|---|
| מה | ₪200 חד-פעמי על הקמת החנות | מה שקונה משלמת על מוצר |
| למי | למנהלת | ישירות לילדה |
| איפה בקוד | `payment_*` · `lib/pricing.ts` | `payout_*` · `lib/payouts.ts` |
| מי מגדיר | המנהלת מאשרת בחמ"ל | הילדה בהגדרות |

הילדה בוחרת בהגדרות איך משלמים לה — **ביט · פייבוקס · מזומן** (+ הערה חופשית כמו
"ביט לאמא: 052-…"). מה שסימנה מוצג לקונה בגיליון ההזמנה ונכנס להודעת הוואטסאפ.
אנחנו לא מסלקים, לא מאמתים ולא סופרים את הכסף הזה — `payout_*` הן העדפות תצוגה בלבד,
והילדה מסמנת "שולם" בעצמה. אין עמלה.

## 🔗 רשת החנויות — איך ילדה מגיעה לכאן

בתחתית כל חנות פעילה יש "גם לך יש דברים למכור → פתחי חנות משלך", שמוביל ל-`/?ref=<slug>`.
דף הנחיתה מזהה את המקור ("הגעת מהחנות של נועה — עכשיו תורך"), סופר את הלחיצה
(`ref_clicks`), והשיוך נשמר ב-`referred_by` ביצירת החנות. **הסלאג מאומת בשרת** — הלקוח
יכול לשלוח כל דבר.

בחמ"ל יש טאב **רשת**: אשכולות (מי הביאה את מי, בעץ), כמה חנויות הגיעו מהפניה, וכמה
מהלחיצות הפכו לחנות בפועל. זה מה שמראה כיתה שנפתחה מחנות אחת.

**`/dashboard/share` — "להפיץ"**: שש הודעות מוכנות (פתיחה · לחברה אחת · מוצרים חדשים ·
סטורי · נשארו אחרונים · למשפחה), מותאמות אוטומטית לשם החנות, ללינק ולמוצר הראשון.
היא בוחרת, עורכת אם בא לה, ושולחת — בלי להמציא ניסוח. `lib/share-texts.ts`.

## חוקים קשיחים שמיושמים בקוד

- `slug` אקראי (5 תווים) · `noindex,nofollow` בכל דף חנות · אין שדה כתובת בשום מקום
- הטלפון של הילדה **לא יושב ב-HTML** — מוחזר מהשרת רק אחרי יצירת הזמנה
- כל תמונה עוברת קנבס → webp ריבועי, ה-EXIF (כולל GPS) נמחק
- הקלטת וידאו: 5 שניות, 720×720, `audio: false` (החלטת פרטיות)
- מלאי יורד ב"שולם" (פונקציית DB אטומית), לא ביצירת הזמנה
- מכסות: 20 מוצרים · 25MB מדיה לחנות · 5 הזמנות מ-IP ליום · 3 חנויות לאימייל
- מחיקת מוצרים היא תמיד soft delete (`deleted_at`)
- החנות הפומבית נקראת בשרת בלבד עם service role ושדות מפורשים — `contact_phone` והאימייל לא דולפים
- ההרשמה היא של הילדה בלבד (אימייל + סיסמה). עמודות `parent_*` קיימות בסכמה אך אופציונליות (מיגרציה 0002) — אפשר להחזיר מעורבות הורה בעתיד בלי שינוי סכמה
