# דוכן — תוכנית בנייה

> משלים את `duchan-spec.md`. שם — מה המוצר. כאן — איך בונים אותו, כמה זה עולה, ואיך ילדה מתחילה לבד.

## 0. בדיקת המוקאפ

עברתי על הקובץ מקצה לקצה:

| בדיקה | תוצאה |
|---|---|
| מזהים כפולים | אין |
| הפניות JS לאלמנטים שלא קיימים | אין |
| תגיות לא סגורות (div / video / button) | 101/101 · 4/4 · 29/29 |
| משתני CSS בשימוש ללא הגדרה | אין |
| תחביר JS | תקין |

הפלואו המלא נסגר: מוצר חדש → נשמר → מופיע בחנות → נוסף לסל → הזמנה → וואטסאפ → כרטיס בדשבורד → "שולם" → מלאי יורד → "אזל" → המוצר צונח לתחתית הרשת. כל צעד מעדכן את שני הצדדים.

## 1. ארכיטקטורה: דיפלוי אחד, אין ספור חנויות

**זו הנקודה הכי חשובה בכל התוכנית.** אין "שכפול" ואין דיפלוי לכל ילדה. יש אפליקציה אחת שרצה במקום אחד, וכל חנות היא **שורה בטבלה**.

```
app.duchan.co          → הרשמה + דשבורד (כל הבעלות, אותו קוד)
duchan.co/s/{slug}     → חנות פומבית, נטענת לפי ה-slug
```

חנות מספר 1 וחנות מספר 800 מריצות בדיוק את אותם קבצים. כשאת מתקנת באג — הוא מתוקן בכל החנויות בו-זמנית. זה ההבדל בין מוצר לבין 800 פרויקטים שאת מתחזקת.

**עלות תחזוקה של חנות נוספת: אפס.** לא שרת, לא דומיין, לא דיפלוי, לא הגדרה. שורה ב-`stores`.

### ושכפול יזום על ידך

לצד ההרשמה העצמית, מסך אדמין עם כפתור אחד: `יצירת חנות`. הוא מייצר שורה ריקה + `claim_token`, ומחזיר לינק חד-פעמי. את שולחת אותו לאמא, היא נכנסת, מגדירה סיסמה, והחנות שלה. שימושי לחוג, לכיתה, לכל קבוצה שאת רוצה להכניס במכה.

## 2. עלות: איך זה נשאר אפס

### הסטאק

| שכבה | שירות | חינם עד |
|---|---|---|
| אירוח | Cloudflare Pages / Workers | בלתי מוגבל למעשה |
| דאטהבייס + Auth | Supabase | 500MB DB · 50K משתמשים |
| **מדיה** | **Cloudflare R2** | **10GB · egress חינם** |

### למה R2 ולא Supabase Storage — החישוב שקובע

זו הנקודה שמפרקת את התקציב אם מפספסים אותה.

חנות עם 6 מוצרי וידאו = כ-5MB לצפייה בעמוד. ב-Supabase יש 5GB egress חינם לחודש:

```
5GB ÷ 5MB = כ-1,000 צפיות בעמוד. בחודש. לכל החנויות ביחד.
```

זה נגמר בשבוע הראשון. **ב-R2 ה-egress חינם לחלוטין** — משלמים רק על אחסון. אותו קוד, אותו S3 API, הבדל של מאות שקלים בחודש.

### תקציב אחסון

| פריט | גודל |
|---|---|
| תמונת מוצר (900×900 webp) | ~120KB |
| וידאו (5ש׳ · 720×720 · 1.5Mbps) | ~900KB |
| פוסטר | ~60KB |
| **חנות מלאה (20 מוצרים)** | **~22MB** |

**10GB ÷ 22MB ≈ 450 חנויות בחינם.** כשתגיעי לשם, R2 עולה $0.015 לג׳יגה — כלומר חנות 451 תעלה לך שליש אגורה בחודש.

### שתי מלכודות

**Supabase משהה פרויקטים אחרי שבוע ללא פעילות.** בהתחלה, כשיש שתי חנויות, זה יקרה. פינג יומי מ-Cron של Cloudflare פותר.

**Vercel Hobby אסור לשימוש מסחרי.** דוכן לא גובה כסף, אז זה כנראה בסדר — אבל Cloudflare Pages לא מטיל את ההגבלה הזו בכלל, ולכן הוא הבחירה השקטה יותר.

## 4. סלף-אונבורדינג

**היעד: מנחיתה ועד לינק שאפשר לשלוח — פחות מ-4 דקות, בלי שאף אחד יסביר כלום.**

### המהלך שקובע: בונים לפני שנרשמים

הרשמה לפני ערך = נטישה. לכן הסדר הפוך: הילדה מקימה חנות, מוסיפה מוצר אחד, בוחרת ערכה — **ורק אז** נרשמת כדי לשמור. באותו רגע היא כבר ראתה משהו שהיא לא רוצה לאבד.

| דקה | מסך | פעולה |
|---|---|---|
| 0:00 | נחיתה | "מה שם החנות שלך?" — שדה אחד, בלי אימייל |
| 0:20 | בחירת ערכה | 6 אריחים, תצוגה מקדימה חיה |
| 0:40 | מוצר ראשון | מצלמה נפתחת ישר. תמונה, שם, מחיר |
| 2:00 | **החנות שלך מוכנה** | תצוגת החנות האמיתית, במסך מלא |
| 2:20 | שמירה | טלפון + אימייל הורה + סיסמה |
| 3:00 | הלינק שלך | `העתקה` · `שיתוף בוואטסאפ` |

מסך 2:00 הוא הציר. עד אליו לא ביקשנו כלום — רק נתנו.

### רשימת השלמה בדשבורד

עד שהיא נסגרת, פס בראש מסך ההזמנות:

```
החנות שלך 3 מתוך 4  ▓▓▓░
✓ מוצר ראשון   ✓ ערכת נושא   ✓ שם
○ תמונת קאבר  →
```

נעלמת לגמרי כשמסיימים. לא באנר קבוע.

### מה מחליף תמיכה

- **מצב ריק שמלמד** — "עוד לא הגיעו הזמנות. שלחי את הלינק לחברות שלך [העתקה]" הוא ההוראה היחידה שצריך.
- **שגיאות שאומרות מה לעשות** — "הסרטון ארוך מדי — עד 5 שניות", לא "העלאה נכשלה".
- **וידאו של 40 שניות** בעמוד הנחיתה: ילדה מוסיפה מוצר, מהתחלה ועד הסוף. מחליף דף עזרה שלם.
- **מייל אחד להורה** בהרשמה, עם לינק לסגירת החנות. זו כל התמיכה שנדרשת מצדך.

## 5. שלבי בנייה

| # | שלב | מוכן כאשר |
|---|---|---|
| 1 | סכמה · RLS · Auth · דף חנות פומבי | slug ריק נטען ומציג "החנות סגורה" |
| 2 | מוצרים: CRUD + תמונות (חיתוך לריבוע, מחיקת EXIF) | 3 מוצרים עולים מהטלפון תוך דקה |
| 3 | חנות: רשת · כרטיס מוצר · סל | הלינק נראה טוב בתצוגה של וואטסאפ |
| 4 | הזמנה → וואטסאפ + מסך הזמנות | הודעה נפתחת, כרטיס מופיע |
| 5 | מלאי · אזל · ניכוי ב"שולם" | מוצר שנגמר יורד לתחתית |
| 6 | ערכות נושא + קאבר + תצוגה מקדימה חיה | החלפת ערכה משנה הכל מיידית |
| 7 | **אונבורדינג: בנייה לפני הרשמה** | ילדה מגיעה ללינק ב-4 דקות בלי עזרה |
| 8 | וידאו: הקלטה · פוסטר · IntersectionObserver | 6 סרטונים ברשת בלי לתקוע גלילה |
| 9 | אדמין: רשימה · השבתה · יצירת חנות + claim | את פותחת חנות ושולחת לינק |

**1–6 זה המוצר. 7 הוא מה שהופך אותו למשהו שמתפשט בלעדייך. 8 הוא מה שהופך אותו לסקוויש.**

שלב 8 אחרי 7 בכוונה: וידאו הוא הדבר הכי כיף והכי יקר. תגלי אם הן בכלל מוסיפות מוצרים לפני שתפתחי את הברז שאוכל אחסון.

## 6. מה מפרק את מודל האפס-עלות

הצגה כנה של הסיכונים, לפי סדר הסבירות:

1. **וידאו מהגלריה במקום הקלטה.** 50MB במקום 900KB. אם מתברר שהילדות מצלמות קודם ומעלות אחרי, את צריכה חיתוך אורך בצד לקוח — וזה פרויקט בפני עצמו. עד אז: דחייה מפורשת מעל 10 שניות.
2. **חנות אחת שמתפוצצת.** אם כיתה שלמה נכנסת לחנות אחת, ה-egress הוא עדיין אפס ב-R2, אבל Supabase יקבל עומס קריאות. קאשינג של דף החנות ל-60 שניות פותר.
3. **תמונות ללא חיתוך.** אם מדלגים על הקנבס, כל תמונה היא 6MB במקום 120KB — פי חמישים באחסון, ועם ה-GPS של הבית בפנים.

## 7. איך יודעים שזה עובד

שלוש חנויות, שבוע:

- **כמה הוסיפו מוצר שני בלי שביקשת** ← המדד היחיד שקובע
- כמה סיימו אונבורדינג לבד, בלי שאף אחד ישב לידן
- כמה זמן עבר מנחיתה ועד העתקת הלינק
- יחס `sent` → `paid` (אם נמוך — יש הרבה הזמנות רפאים, וצריך לחשוב מחדש על הכפתור)

אם אף אחת לא חזרה ביום השני — למדת משהו זול מאוד, ולא בנית מערכת סליקה בשביל זה.
